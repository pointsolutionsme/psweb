EU Data Sovereignty & Sovereign AI Routing

Keep your prompts, tool outputs, and embeddings inside EU jurisdiction. No US CLOUD Act exposure.

01

The Residency Attribute & Tiered Routing

Every model deployment in the gateway catalog carries a residency attribute, for example EU or US, and a maximum data tier. The policy decision point blocks any request that would send data to a deployment whose residency or tier is insufficient. Fallback targets must satisfy the same tier and residency.

  • Public / Internal: may use global providers where terms allow.
  • Confidential: prefers EU-routed deployments with an Article 28 DPA and zero retention.
  • Restricted: blocked by default; allowed only through an exception flow per use case.

The session tier is set at runtime when a tool returns data. Once Confidential data enters the conversation, the request cannot be routed to a model approved only for Internal. DLP detectors can raise the session tier as a second signal.

02

EU API Gateways vs. Sovereign Specialists

EU routing comes in three classes, from least to most control. The right choice depends on the data tier, latency tolerance and how much of the stack the customer wants to operate.

Provider class Examples What it provides Cost / trade-offs
EU API gateways Requesty EUrouter Eden AI OpenAI-compatible aggregation of open-weight models routed only through EU data centers. Article 28 DPAs, zero-retention payload defaults. Roughly 5-15% premium over global aggregators; smaller catalog; EU GPU pools can mean peak-hour latency.
Sovereign specialists Apertus AI Nordference Built for regulated industries. NIS2 compliance, zero retention, strict sovereignty guarantees. Higher prices, narrower model catalog.
Managed EU cloud inference Scaleway OVHcloud IONOS Open-weight models on EU infrastructure via managed endpoints or GPU instances. No third-party gateway. Customer operates more of the stack; closest to self-hosting without owning GPUs.

The EU premium reality

For mainstream open models such as Qwen 2.5 72B and Kimi K2.6, EU gateway prices are within about 5% of global aggregators; Requesty states it adds only a ~5% margin. The premium reaches 10-15% mainly on new or supply-constrained models. Provider prompt caching offsets part of the difference: cache-hit input costs for DeepSeek V4 Flash can drop to $0.007 per 1M tokens.

03

Article 28 DPAs & Zero-Retention Defaults

EU providers operate under GDPR Article 28 Data Processing Agreements that legally bind them to the customer's data protection rules. This is a contractual default, not an opt-in privacy mode.

  • Zero-retention payloads: gateway logs carry metadata only; payload logging is off by default for Confidential and above.
  • No training use: EU DPAs explicitly forbid using API traffic to train, fine-tune or improve future models.
  • No CLOUD Act exposure: data processed by EU providers on EU infrastructure is outside the reach of US disclosure orders directed at US-controlled companies.
  • NIS2 alignment: sovereign specialists such as Nordference are NIS2-compliant for essential and important entities.

Contrast this with US providers that often require manual toggling of a "privacy mode" to stop prompt logging. The EU default removes that operational dependency and the associated audit risk.

04

Localized Memory & Vector Stores

Embeddings of Confidential content and above never leave the platform. The memory service scopes data per user, per agent, per team and organization knowledge, and each item carries the tier of its source.

  • Vector store: pgvector on managed PostgreSQL; embeddings stay in-house.
  • Scoped memory: Mem0 for user, agent and session scopes. Cross-scope reads are blocked by policy and tested in the evaluation suite.
  • Self-hosted embeddings: BGE via Infinity keeps Confidential text out of provider embedding APIs.
  • Retention and deletion: TTL per scope; users can view and delete personal memory; offboarding triggers verified deletion propagated to backups.
FAQ

Common Questions

Does using an EU AI gateway protect against the US CLOUD Act?

Yes, for data processed by EU providers on EU infrastructure. The US CLOUD Act allows US authorities to compel US-controlled companies to disclose data regardless of where it is physically stored. EU-based providers that are not US-controlled and operate under EU jurisdiction are outside the direct reach of those disclosure orders. Data is also covered by Article 28 Data Processing Agreements with zero-retention payload defaults and explicit contractual prohibitions on training use.

How is Restricted data handled differently than Confidential data?

Confidential data is routed to EU-resident API gateways with Article 28 DPAs and zero-retention defaults. Restricted data is blocked by default and allowed only through an exception flow approved per use case. When approved, Restricted data uses sovereign specialists such as Apertus AI or Nordference, managed EU cloud inference on Scaleway, OVHcloud or IONOS, or a customer-operated vLLM deployment on EU infrastructure. Restricted data also requires dedicated deployments, full audit and alerting.
