01

The AI Gateway

The AI Gateway is the single OpenAI-compatible API endpoint for every model in the enterprise, whether commercial, open-weight or self-hosted. Provider changes become configuration edits, not rewrites. Because all provider credentials live here, no team needs to hold a raw provider key.

  • Unified access: one API shape for Anthropic, Google, OpenAI, Bedrock and self-hosted models.
  • Virtual keys: scoped, revocable keys bound to an IdP identity with short expiry and automatic rotation.
  • Reliability: retry, cross-provider fallback and load balancing; fallback targets must satisfy the same data tier and residency.
  • Cost control: budgets per team, key and agent; soft alerts and hard blocks at the gateway.
  • Production deployment: at least three replicas across zones; managed PostgreSQL for state; Redis for rate limits; exposed only through the corporate ZTNA.

Reference implementation: LiteLLM with its Rust hot path in production. Where SSO, RBAC at scale and audit logs must stay in the free tier, the gateway can be fronted with Kong AI Gateway 2.0.

02

Inline Guardrails & DLP

Every request and response passes through a guardrail chain that enforces policy without adding unacceptable latency. The chain runs on CPU for interactive use and escalates sampled or flagged traffic to deeper classification asynchronously.

  • Injection filter: Llama Prompt Guard 2 runs on CPU in under 20 ms.
  • PII and secrets masking: Presidio detects and redacts identifiers, credentials and customer data before storage.
  • Policy rails: NeMo Guardrails enforces topic and workflow constraints.
  • Policy decision point: OPA evaluates tier checks and custom rules on every model call and tool call.
  • Async classification: flagged or sampled traffic is classified by Llama Guard 4 where a GPU is budgeted.
03

The MCP Tool Hub

The Tool Hub is the single door to enterprise systems. Source code, project management, documents, CRM, ERP and observability are exposed as MCP tools through one authenticated endpoint. Agents and IDE assistants never hold system credentials, and no client connects to a backend MCP server directly.

How it works

  • MCP gateway: reference implementation is agentgateway from the Linux Foundation. It authenticates callers via OAuth 2.1, authorizes each tool call with per-tool CEL policies, exchanges or injects downstream credentials, applies rate limits and output guardrails, and emits OpenTelemetry spans.
  • Virtual servers: curated toolsets per role or agent, for example "engineering-read", "sre-operations" or "sales-assistant". Keeps tool counts small, which improves selection accuracy and lowers token cost.
  • Authentication patterns: on-behalf-of token exchange for systems federated with the IdP; per-user OAuth for SaaS without token exchange; scoped service accounts for ERP; workload identity for cloud and Kubernetes APIs.
  • Tool design: custom task-level tools built with FastMCP, filtered to read-only by default; write variants are separate servers with their own identity and approval routing.
04

Tool Poisoning & Supply Chain Defense

Silent changes to tool definitions, the "rug pull" threat, are blocked by treating the tool registry as immutable code. Every definition is hashed, scanned and approved before it reaches production.

  • Definition pinning: the registry stores a hash of each tool's name, description and schema. The gateway blocks changed definitions until re-approved.
  • CI scanning: three-stage pipeline — mcp-scan (OWASP fast gate), NVIDIA SkillSpector for skill packages, and AI-Infra-Guard for MCP servers before registry publication.
  • Isolation: one namespace per backend server, non-root containers, read-only filesystems and network policies that allow egress only to the target system.
  • Build integrity: pinned versions, signed images, SBOMs and vulnerability scans; no runtime downloads from package managers.
FAQ

Common Questions

What is an MCP Tool Hub?

An MCP Tool Hub is a centrally governed gateway for Model Context Protocol tools. It exposes enterprise systems such as source code, project management, documents and CRM as a single curated endpoint, so agents and IDE assistants never hold system credentials or connect to backends directly. The hub authenticates each call, authorizes per tool and per user, brokers credentials, applies rate limits and output guardrails, and emits an audit trace for every action.

How do you prevent AI prompt injection?

Prompt injection cannot be eliminated completely, but the platform reduces frequency and limits blast radius through a layered defence: tool outputs pass output guardrails before reaching the model; results are tagged as data and separated from instructions in the agent prompt; each agent has a minimal allow-listed tool set; egress is restricted to prevent exfiltration; and anomaly rules in the SIEM detect unusual tool sequences. High-impact tools remain behind human approval even with all controls enabled.
