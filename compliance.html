EU AI Act: Deployer Duties

Article 26 of the EU AI Act imposes deployer duties including use in accordance with instructions, human oversight, input quality and log retention. The platform generates evidence for each obligation from built-in controls rather than after-the-fact documentation.

Use in accordance with instructions Agent profiles, system prompts and tool scopes versioned in Git Git history of approved prompts and profiles
Human oversight Slack Block Kit approvals for write and destructive actions Approval ID, action hash, approver, timestamp, Slack signature

02

ISO/IEC 42001 & NIST AI RMF

ISO/IEC 42001 requires an AI management system: roles, risk assessment, controls and continuous monitoring. The NIST AI RMF frames the same work as Govern, Map, Measure and Manage.

  • Roles and ownership: section 8 of the reference architecture assigns owners to the gateway, policies, agent runtime, individual agents, observability, FinOps and GitOps repositories.
  • Risk assessment: the four-tier classification model maps every tool, agent, virtual key and model deployment to a risk level; the policy decision point enforces it at runtime.
  • Monitoring: observability (OpenTelemetry, Prometheus, Grafana) and SIEM detections cover guardrail hits, policy denials, tier violations and unusual tool sequences.
  • FinOps and SLOs: budgets, cost attribution and service-level objectives provide measurable control and continuous improvement loops.
03

GitOps as the Ultimate Audit Trail

The desired state of the entire platform lives in source control. Prompts, configurations, policies, tool definitions, agent profiles and deployments are versioned files. Every change reaches production through a reviewed pull request, automated checks and Argo CD sync.

  • Git history is the audit trail: who proposed, reviewed and approved every change; what automated checks passed; when it was deployed.
  • Automated checks: lint, schema validation, OPA policy unit tests, secret scanning, container and dependency scans, image signing, skill and MCP definition scans, and agent evaluation suites with regression thresholds.
  • Drift control: Argo CD self-heal reverts manual changes and raises alerts; admin UIs are read-only in production.
  • Policy as code: OPA Rego policies are stored in Git and tested in CI; the same engine evaluates runtime authorization and Kubernetes admission.
  • Dependency freshness: Renovate opens pull requests for components, images, MCP servers and model price tables; each update passes the same gates.
04

Privacy by Default & Employee Monitoring

GDPR and works-council consultation require a clear logging privacy policy. The default balances audit needs against employee privacy: metadata is always logged, but prompt content is off by default for human interactive use.

  • Metadata always logged: user, model, tokens, cost, latency, tools, policy result.
  • Content off by default for interactive use; enabled per team on request or captured only on policy violation.
  • Agents and automations: prompt and response content logged for debugging and audit, with retention per use case.
  • Redaction: secrets and PII are masked before storage in all cases.
  • Governance: the logging privacy policy is owned by Security and HR/Legal with employee-representative consultation.
FAQ

Common Questions

How does GitOps help with ISO 42001 audits?

ISO 42001 requires an AI management system with controlled policies, roles, risk assessment and monitoring. GitOps makes every change to prompts, policies, tool definitions, guardrails and model configurations a reviewed, tested, versioned pull request. The Git history becomes the audit trail: who changed what, when, why, and which automated checks passed. Argo CD self-heal prevents manual drift, so the running state always matches the approved state.

How do you handle human oversight for AI agents?

Human oversight is enforced at the action layer, not bolted on afterwards. Read operations within a user's scope run autonomously. Writes to production or business records require approval via Slack Block Kit interactive messages. The agent workflow pauses at a LangGraph interrupt; a posted message shows the action, arguments and context with Approve and Reject buttons. The click is verified with Slack request signature, nonce replay protection, approver binding to an IdP role, and a hash-chained audit record.
