How a Request Moves Through the Platform

Every governed request starts with identity and passes through two control points — the AI Gateway for models and the Tool Hub for systems — with two cross-cutting planes that enforce policy and watch cost.

01

Identity (SSO)

Every request starts with who you are. The identity provider authenticates the user or agent, returns group membership, and maps it to a clearance tier. The virtual key handed to the gateway is bound to that IdP identity — not to a shared service account — so every downstream action is traceable to a person.

02

User channel

The request enters through a channel: an agent, an internal app, an IDE assistant or an automation. Agents plan the call and pick tools, but they do not hold credentials to your systems. They only decide what to ask and interpret the sanitized result.

03

AI Gateway

The gateway is the single door to every model. It applies guardrails, checks policy, and routes by residency attribute. Confidential data goes only to EU-resident providers under Article 28 DPAs with zero-retention defaults; Restricted data can be routed to a sovereign EU provider or to a self-hosted deployment.

04

Model

The model generates a response or a structured intent. It never executes tools directly, and it never holds credentials. If the response requires an action against your systems, the request is delegated back to the Tool Hub inside your boundary.

05

Tool Hub

The Tool Hub is the single door to your systems. It authenticates each call via the IdP, authorizes per tool and per user and brokers credentials without exposing them. Production writes go through approval gates; reads are allowed only within the caller's own permissions.

06

Your systems

Your existing systems — code, tickets, documents, CRM, ERP — execute the action. The model only ever sees a sanitized result back. Because tool execution and credentials live inside your boundary, sovereignty does not depend on choosing the right model provider.

07

Security and policy

One policy decision point evaluates every model call and tool call. Guardrails check input and output, classify the request against Public / Internal / Confidential / Restricted tiers and route sensitive data to the right model and approval path. Decision is separated from enforcement: the gateway and tool hub consult the PDP, then enforce it.

08

Observability and cost

Every request emits a trace that follows it end to end: channel, agent, model call, tool call, policy decision and approval. Usage and cost are attributed per team, agent and virtual key; budgets trigger soft alerts and hard blocks at the gateway. Metadata and audit logs flow to the existing SIEM; content is logged only where policy allows.
